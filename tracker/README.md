# 交易員追蹤（前瞻紀錄）

目的：把「今天選出來的交易員」之後的真實表現記下來。回測再好都可能偷看或存活偏誤，**選人之後的前瞻紀錄才是最後的驗證**。

- 資料來源：Hyperliquid 公開 info API（`api.hyperliquid.xyz/info`），不需金鑰、不下單。任何人都能用地址在 https://app.hyperliquid.xyz/explorer 自己查證。
- 執行：`.github/workflows/trader-tracker.yml` 每 6 小時（UTC 00:17、06:17、12:17、18:17）跑一次 `run_tracker.py`，結果追加到 **tracker-data** 分支（一般 commit，不覆蓋歷史）。
- 選人紀錄：`watchlist.csv` 在 main，git 歷史就是「什麼時間選了誰」的證據。**只追加、不刪列**；要移除就把 `active` 改成 0。

## watchlist.csv 欄位

| 欄位 | 說明 |
|---|---|
| addr | 地址（0x…，小寫） |
| label | 代號（研究報告裡的編號） |
| added_utc | 加入名單時間（UTC，`YYYY-MM-DD HH:MM`）；前瞻績效從這之後的第一個權益點起算 |
| active | 1＝追蹤中，0＝已移除（保留紀錄） |
| source | 選人依據（例如 T-03L 規則、版本） |
| grade | 檢查清單等級（甲／乙／丙；今天最高乙，前瞻紀錄 ≥ 4 週且贏同期 BTC 才可能升甲）；「對照」＝隨機對照組 |
| note | 備註（帳戶類型、主要風險）。標「可觀察」＝丙級裡沒有排除項、第 1 節全 ✅、扣掉「證據還不夠」類（4.3、6.2、6.3、6.4）後 ⚠️ ≤ 2 的人（2026-11-06 起，研究系統 Q-03）：不跟單，只觀察證據有沒有累積起來 |

## 對照組（檢驗「選人」本身有沒有用）

名單裡 grade＝對照 的地址是隨機抽的，和候選人同時加入、同樣追蹤，共四批：

| 批次 | 人數 | 從哪裡抽 | 對應的候選人 |
|---|---|---|---|
| v1（11/04） | 20 | 候選宇宙（權益 ≥ 10 萬、近 30 天有交易、生涯損益 > 0、非金庫），種子 20261105 | v1 的乙 1、丙 18 |
| v1.2（11/05） | 7 | v1.2 新篩到的帳戶，種子 20261106 | 丙-20～26 |
| Q-03（11/06） | 4 | 第 1 階段每個門檻鬆一格才進得來的 464 人，種子 20261106 | 丙-27～30（同一群人裡的可觀察者） |
| Q-04 小帳戶（11/06） | 8 | 權益 1 萬～10 萬的小帳戶宇宙（其他條件同候選宇宙）裡沒進逐項檢查的 1,184 個，種子 20261106 | 丙-31～38（小帳戶宇宙逐項檢查後的丙） |

名單（乙＋丙）的前瞻報酬要同時贏 BTC 和對照組中位數，才算選人有效。這條規則在看到任何前瞻結果之前寫定（2026-11-05）。每一批也可以和自己對應的候選人比，但每批人數少，只當參考。

## 產出（tracker-data 分支）

| 檔案 | 內容 |
|---|---|
| summary.md | 最新摘要：群體淨多空、部位變化、前瞻績效、實際槓桿 |
| forward.csv | 每人自加入起：TWR（全帳戶分母、合約帳戶分母）、同期 BTC、超額、最大回撤 |
| series/{addr}.csv | 扣入出金的權益指數（約每 2 小時一點） |
| equity/YYYY-MM.csv | 每次快照每人一列：全帳戶與合約帳戶權益、多空名目、實際槓桿（兩種分母） |
| positions/YYYY-MM.csv | 每個部位：設定槓桿、逐倉／全倉、強平價、離強平距離 |
| events/YYYY-MM.csv | 部位變化：初始、開倉、加碼、減碼、平倉、翻向 |
| fills/YYYY-MM.csv | 新成交（liquidation 欄：self＝自己被強平、counterparty＝接到別人的強平單） |
| consensus/YYYY-MM.csv | 名單群體各幣的淨多空 |
| alerts.md | 被強平、離強平價 < 5%、單次新部位 ≥ 權益 1 倍、追蹤以來回撤跨過 20／30／40／50／70% |

## 口徑（和研究系統一致）

- **報酬**：分子＝合約損益（不含現貨漲跌），用 Modified Dietz 扣入出金。分母：
  - 全帳戶（Hyperliquid 算的總權益）：主口徑。
  - 合約帳戶：只對 default／disabled 模式有意義（獨立保證金池），統一帳戶不列。
- **總權益**一律用 Hyperliquid portfolio 的即時總權益。實測（2026-11-04）：多數活躍帳戶是 `unifiedAccount` 或 `portfolioMargin` 模式（info `userAbstraction` 查得到），合約權益已含在現貨 USDC 裡，合約＋現貨相加會重複計算；portfolioMargin 的現貨 USDC 可為負（借款），其他現貨直接當保證金。
- **實際槓桿**＝合約部位名目加總（含 HIP-3 自建合約 dex）÷ 總權益。「只看合約帳戶」的槓桿只對 default／disabled 模式列出。另列「含現貨曝險」＝（合約名目＋非穩定幣現貨）÷ 總權益。設定槓桿（leverage.value）只記錄，不當風險指標。
- **基準**：同期 BTC 買進持有（1 小時 K 收盤）。
- portfolio 歷史點時間固定、最後一點是抓取當下的即時點；權益指數用「共同歷史點」接續，追蹤中斷 7～30 天也接得上（用 month 視窗），超過就標 gap。

## 限制

- 每次對主合約和所有 HIP-3 dex（`perpDexs` 列出的）各查一次 clearinghouseState；交易員在別的交易所的部位看不到。
- 同一人可能有多個地址；對沖可能在別處。
- 前瞻報酬沒有扣跟單延遲、滑價、手續費；實際跟單請看研究系統 T-06／T-07 的延遲模擬。
